# QTprojects

[![CI](https://github.com/Apisteftos/QTprojects/actions/workflows/ci.yml/badge.svg)](https://github.com/Apisteftos/QTprojects/actions/workflows/ci.yml)

A hands-on Qt 6 tutorial in modern **C++23**, built with **CMake**.
It starts with the basics (setting up a project, opening a first window, creating a button) and builds up step by step to signals and slots, architecture patterns, networking, databases, threads, testing and CI.

Every example is a small, self-contained project with its own `README.md` (explanation and code), a `main.cpp` and a `CMakeLists.txt`, so you can read it, build it and run it on its own.

## 1. What Is Qt?

**Qt** (pronounced "cute") is a cross-platform C++ application framework. It gives you much more than a GUI toolkit: strings, containers, files, JSON, networking, databases, threads, a timer and event system, a testing framework and a UI layer, all designed to work together. The same code builds on Linux, Windows, macOS, Android, iOS and many embedded systems.

Qt is available under open-source licences (LGPL and GPL) and under a commercial licence. Check the licence terms before you ship a product.

### What Qt adds on top of standard C++

| Feature | What it means |
|---------|---------------|
| **Meta-object system** | Adds runtime information to classes that derive from `QObject`: signals and slots, properties, `qobject_cast`, dynamic property access. It is generated by the **moc** tool at build time. |
| **Signals and slots** | A type-safe way for objects to talk to each other without knowing each other. An object *emits* a signal, and any connected slot (function or lambda) runs. |
| **Event loop** | `QApplication::exec()` waits for events (mouse, keyboard, timers, network) and delivers them to objects. Almost every Qt program is built around it. |
| **Parent-child ownership** | A `QObject` with a parent is deleted automatically when the parent is deleted, so most widgets need no manual `delete`. |
| **Implicit sharing** | `QString`, `QList`, `QByteArray` and similar classes share their data and copy it only when it is modified. Passing them by value is cheap. |
| **Unicode strings** | `QString` stores text as UTF-16 and converts easily to and from `std::string` and UTF-8. |

### Qt modules

Qt is split into modules. You link only the ones you use.

| Module | Purpose |
|--------|---------|
| **Core** | Non-GUI base: `QObject`, `QString`, containers, events, timers, files, JSON, threads |
| **Gui** | Windowing, painting, images, fonts, input events |
| **Widgets** | Classic desktop UI controls (buttons, labels, line edits, tables, dialogs, layouts) |
| **Network** | TCP, UDP, HTTP clients and servers, SSL |
| **Sql** | Database access (SQLite and others) with models for views |
| **Concurrent** | High-level helpers for running code on other threads |
| **Test** | QTest, the unit-testing framework |
| **Qml / Quick** | Declarative UI written in QML, with JavaScript logic and a GPU-accelerated scene graph |

### Build tools that come with Qt

| Tool | Job |
|------|-----|
| **moc** (Meta-Object Compiler) | Reads headers with `Q_OBJECT` and generates the code behind signals, slots and properties |
| **uic** (User Interface Compiler) | Turns a `.ui` form designed in Qt Designer into C++ code |
| **rcc** (Resource Compiler) | Embeds files such as icons and images into the executable |

With CMake, `AUTOMOC`, `AUTOUIC` and `AUTORCC` run these tools automatically.

## 2. What Are Qt Widgets?

**Qt Widgets** is Qt's module for classic desktop user interfaces. A *widget* is a visual element on the screen: a window, a button, a text field, a table. Every widget derives from `QWidget`.

```cpp
#include <QApplication>
#include <QLabel>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QLabel label("Hello, Qt!");
    label.show();

    return app.exec();
}
```

Key ideas:

- **`QApplication`** manages the application: it holds the event loop and global settings. There is exactly one per program.
- **Widgets form a tree.** A window contains a layout, the layout contains buttons and labels, and every child has a parent.
- **Layouts** (`QVBoxLayout`, `QHBoxLayout`, `QGridLayout`) position and resize widgets automatically, so you rarely set pixel coordinates.
- **`QMainWindow`** is the standard application window, with a menu bar, tool bars, a central widget and a status bar.
- **Qt Designer** lets you build a window visually. It saves a `.ui` file that `uic` converts to C++.

### Widgets or QML?

| | Qt Widgets | Qt Quick / QML |
|---|-----------|----------------|
| Style | Imperative C++ | Declarative QML plus JavaScript |
| Best for | Desktop tools, forms, data-entry applications, editors | Touch screens, animated and custom-styled interfaces, embedded displays |
| Look | Native-style controls | Fully custom |
| Logic | C++ | C++ backend exposed to QML |

Both use the same Qt Core, so the signals and slots, event loop and parent-child ideas apply to both. This tutorial starts with Widgets because they teach the fundamentals clearly, and later chapters also cover QML.

## 4. Building an Example

Every example builds the same way. From inside an example folder:

```bash
cmake -S . -B build
cmake --build build
./build/<executable-name>
```

You can also open the example's `CMakeLists.txt` in Qt Creator, select a kit and press **Run**.

If your default compiler is older than GCC 14, point CMake at a newer one:

```bash
cmake -S . -B build -DCMAKE_CXX_COMPILER=<path-to-g++-14>
```

## 5. Continuous Integration

Every push and pull request to `main` triggers a GitHub Actions workflow. It builds the examples that include tests and runs them without a display, using Qt's offscreen platform plugin:

```bash
QT_QPA_PLATFORM=offscreen ./build/<test-executable>
```

See `.github/workflows/ci.yml` for the full configuration.
