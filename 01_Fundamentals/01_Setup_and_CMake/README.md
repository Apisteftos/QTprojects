# 01 – Setup and CMake

The first Qt project of the tutorial: a console program without any window. It only proves that three things work together:

- the **C++23 compiler** (needed for `std::println`)
- **CMake**, which describes and builds the project
- **Qt6**, found and linked by CMake

If this example builds and runs, every following example in this tutorial will build on your machine too.

---

## What you need

| Tool | Minimum | Check with |
|---|---|---|
| GCC | 14 (for `<print>`) | `g++ --version` |
| CMake | 3.21 | `cmake --version` |
| Qt | 6.x | `qmake6 --version` |

Install on Ubuntu 24.04:

```bash
sudo apt update
sudo apt install build-essential cmake qt6-base-dev qtcreator
```

> **Compiler note:** The default GCC on Ubuntu 24.04 is version 13, which has no `<print>` header. You need GCC 14 or newer. The compiler is selected in the Qt Creator kit (**Tools → Preferences → Kits**) or on the command line, see [Build and run](#build-and-run). The compiler path is never written into `CMakeLists.txt`, so the same project works on every machine.

## Qt Creator: C++23 and CMake 3.21 by default

Qt Creator's project wizard generates `set(CMAKE_CXX_STANDARD 17)` and `cmake_minimum_required(VERSION 3.16)` in every new project. With C++17, `std::println` does not compile. You could fix both lines by hand in every project, or change the wizard once.

The wizard templates live in the Qt Creator installation. Do **not** edit them there, because a Qt Creator update overwrites the changes. Qt Creator also reads templates from a folder in your home directory. A template there with the **same id** as a built-in template replaces it. The "New Project" dialog still shows one entry per template, and updates do not touch your copy.

Run this once (Qt Creator installed with apt; the system templates are in `/usr/share/qtcreator`):

```bash
D=~/.config/QtProject/qtcreator/templates/wizards/projects
S=/usr/share/qtcreator/templates/wizards/projects

mkdir -p "$D"

for name in consoleapp plaincpp qtwidgetsapplication; do
    [ -d "$D/${name}23" ] || cp -r "$S/$name" "$D/${name}23"
    sed -i 's/set(CMAKE_CXX_STANDARD 17)/set(CMAKE_CXX_STANDARD 23)/; s/^cmake_minimum_required(VERSION [0-9.]*)/cmake_minimum_required(VERSION 3.21)/' "$D/${name}23/CMakeLists.txt"
done
```

| Template | Wizard name in Qt Creator |
|---|---|
| `consoleapp` | Qt Console Application |
| `plaincpp` | Plain C++ Application |
| `qtwidgetsapplication` | Qt Widgets Application |

Check the result:

```bash
grep -n 'CMAKE_CXX_STANDARD \|cmake_minimum' "$D"/*23/CMakeLists.txt
```

Every line must show `23` and `3.21`.

Then:

1. Close Qt Creator and start it again.
2. Create a new project with **File → New Project**. Its `CMakeLists.txt` now starts with `cmake_minimum_required(VERSION 3.21)` and has `set(CMAKE_CXX_STANDARD 23)`.

Leave `wizard.json` in the copied folders unchanged. The copy keeps the original id and name, which is why Qt Creator uses it instead of the built-in template and shows only one entry.

> If a Qt Creator installation from the online installer is used, the system templates are in its own installation folder (for example `.../Tools/QtCreator/share/qtcreator/templates/wizards/projects`). Set `S` to that path.

## The code

### main.cpp

```cpp
// ============================================================
// 01_Setup_and_CMake
// Minimal Qt6 console program that checks that Qt, CMake and
// the C++23 compiler work together.
// ============================================================

#include <QCoreApplication>
#include <QString>
#include <QStringList>

#include <print>

int main(int argc, char* argv[])
{
    QCoreApplication app(argc, argv);

    // === EXAMPLE 1: Qt version ===
    std::println("Qt runtime version:      {}", qVersion());
    std::println("Qt compile-time version: {}", QT_VERSION_STR);

    std::println("");

    // === EXAMPLE 2: QString to std::string ===
    const QString greeting = QStringLiteral("Hello from Qt");
    std::println("{}", greeting.toStdString());

    std::println("");

    // === EXAMPLE 3: Command line arguments ===
    const QStringList arguments = app.arguments();
    std::println("Argument count: {}", arguments.size());
    for (const QString& argument : arguments)
    {
        std::println("  {}", argument.toStdString());
    }

    return 0;
}
```

### CMakeLists.txt

This is the file the Qt Creator wizard generates for a **Qt Console Application**, with the two changes from the section above (`3.21` and `23`):

```cmake
cmake_minimum_required(VERSION 3.21)

project(01_Setup_and_CMake LANGUAGES CXX)

set(CMAKE_AUTOUIC ON)
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTORCC ON)

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(QT NAMES Qt6 Qt5 REQUIRED COMPONENTS Core)
find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Core)

add_executable(01_Setup_and_CMake
  main.cpp
)
target_link_libraries(01_Setup_and_CMake PRIVATE Qt${QT_VERSION_MAJOR}::Core)

include(GNUInstallDirs)
install(TARGETS 01_Setup_and_CMake
    LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}
)
```

## CMakeLists.txt line by line

| Line | Meaning |
|---|---|
| `cmake_minimum_required(VERSION 3.21)` | Refuses to configure with a CMake older than 3.21. |
| `project(01_Setup_and_CMake LANGUAGES CXX)` | Names the project (the wizard uses the folder name) and says it only contains C++ code. |
| `set(CMAKE_AUTOUIC ON)` | Runs `uic` automatically: turns Qt Designer `.ui` files into C++ code. |
| `set(CMAKE_AUTOMOC ON)` | Runs `moc` automatically: generates extra code for classes that use `Q_OBJECT` (signals and slots). |
| `set(CMAKE_AUTORCC ON)` | Runs `rcc` automatically: embeds resource files (images, icons) into the program. |
| `set(CMAKE_CXX_STANDARD 23)` | Compile with `-std=c++23`. |
| `set(CMAKE_CXX_STANDARD_REQUIRED ON)` | Fail if the compiler cannot do C++23, instead of silently falling back to an older standard. |
| `find_package(QT NAMES Qt6 Qt5 REQUIRED COMPONENTS Core)` | Finds out which Qt major version is installed (Qt6 first, then Qt5) and stores it in `QT_VERSION_MAJOR`. |
| `find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Core)` | Loads the **Core** module of that version. `REQUIRED` stops with an error if it is missing. |
| `add_executable(01_Setup_and_CMake main.cpp)` | Defines one program, built from `main.cpp`. |
| `target_link_libraries(... PRIVATE Qt${QT_VERSION_MAJOR}::Core)` | Links the program against Qt Core and adds its include paths. `PRIVATE` means only this program needs it. |
| `include(GNUInstallDirs)` and `install(TARGETS ...)` | Define where `cmake --install` puts the program. Not needed to build or run. |

The `Qt${QT_VERSION_MAJOR}` form works with Qt5 and Qt6. This tutorial uses Qt6 only, but the wizard keeps the generic form, so the tutorial keeps it too.

## main.cpp explained

**Includes**

- `<QCoreApplication>` is the application class for programs without a GUI.
- `<QString>` and `<QStringList>` are Qt's string classes.
- `<print>` is the C++23 header for `std::println`.

**`QCoreApplication app(argc, argv);`**
Every Qt program creates exactly one application object first. It stores the command line arguments and, in later chapters, runs the event loop. Qt has three application classes:

| Class | Use for | Module |
|---|---|---|
| `QCoreApplication` | console programs and services | Core |
| `QGuiApplication` | windows without widgets (QML) | Gui |
| `QApplication` | classic widget programs | Widgets |

**Example 1: `qVersion()` and `QT_VERSION_STR`**
`qVersion()` returns the version of the Qt library that is loaded when the program *runs*. `QT_VERSION_STR` is the version of the Qt headers the program was *compiled* against. They are normally the same. If they differ, two Qt installations are mixed up.

**Example 2: `toStdString()`**
`std::println` does not know how to print a `QString`. You convert it with `toStdString()` first. `QStringLiteral` creates the string at compile time, which avoids a runtime conversion.

**Example 3: `app.arguments()`**
Returns the command line as a `QStringList`. The first entry is the program path, the rest are the arguments you typed.

## Build and run

### With Qt Creator

1. **File → Open File or Project**, select `CMakeLists.txt`.
2. Select a kit that uses GCC 14.
3. Click **Configure Project**, then **Run** (`Ctrl+R`).

### From the command line

From the folder `01_Setup_and_CMake`:

```bash
cmake -S . -B build
cmake --build build
./build/01_Setup_and_CMake
```

Choose the compiler explicitly if the default GCC is too old:

```bash
cmake -S . -B build -DCMAKE_CXX_COMPILER=<path-to-g++-14>
```

For example `/usr/bin/g++-14` when GCC 14 is installed with apt.

> If you change the compiler, delete the build folder first (`rm -rf build`). CMake remembers the compiler from the first configure.

### Expected output

The version numbers depend on your installation:

```
Qt runtime version:      6.4.2
Qt compile-time version: 6.4.2

Hello from Qt

Argument count: 1
  ./build/01_Setup_and_CMake
```

With arguments:

```bash
./build/01_Setup_and_CMake one two
```

```
Argument count: 3
  ./build/01_Setup_and_CMake
  one
  two
```

## Common problems

| Message or symptom | Cause | Fix |
|---|---|---|
| `fatal error: print: No such file or directory` | The compiler is older than GCC 14. | Select a GCC 14 kit in Qt Creator, or configure with `-DCMAKE_CXX_COMPILER=<path-to-g++-14>` in a fresh build folder. |
| `Could not find a package configuration file provided by "Qt6"` | Qt6 development files are not installed. | `sudo apt install qt6-base-dev` |
| New projects still have `CMAKE_CXX_STANDARD 17` | The template copy is missing or Qt Creator was not restarted. | Check that `~/.config/QtProject/qtcreator/templates/wizards/projects/consoleapp23` exists, then restart Qt Creator. Start it with `qtcreator -customwizard-verbose` to see wizard errors in the terminal. |
| Two entries for the same template in "New Project" | The copy's `wizard.json` has a different id than the original. | Keep the original id in the copy. |
| Qt Creator shows red errors, but the build works | Qt Creator's code model (clangd) does not use the C++23 settings of the kit. | Disable clangd in **Tools → Preferences → C++ → Clangd**. |
| Compiler change has no effect | CMake cached the old compiler. | `rm -rf build` and configure again. |
